# Contributing to celoht-investor-book

This repository is documentation-only: it does not contain application
code. Contributions should focus on accuracy, sourcing, and clarity.

## Ground rules

1. **Every material claim needs a source.** If you add a claim, add it to
   [docs/28_SOURCES.md](../docs/28_SOURCES.md) and give it a status in
   [evidence/VERIFICATION_STATUS.md](../evidence/VERIFICATION_STATUS.md).
2. **Never upgrade a status without evidence.** `PLANNED` does not become
   `LIVE`, and `TESTNET` does not become `MAINNET`, without a dated,
   sourced confirmation.
3. **Use canonical terminology.** "CeloHT", "Celo-HaiTi", "USDm", "CELO".
   Do not introduce "Celo-HT" or "cUSD" as current terminology.
4. **No fabricated metrics.** If a number can't be sourced, don't include
   it — write "unavailable" instead.
5. **Historical material stays out of the main narrative** unless it is
   explicitly necessary and clearly marked as historical.

## Workflow

1. Open an issue describing the change and why it's needed.
2. Submit a pull request referencing the issue.
3. In the PR description, list the source(s) for any new or changed claim.
4. A maintainer reviews for accuracy and terminology consistency before
   merging.

## AI-assisted contributions

AI tools may assist with drafting or research, but the human contributor
submitting a PR remains responsible for verifying sourcing, accuracy, and
terminology compliance before submission.
